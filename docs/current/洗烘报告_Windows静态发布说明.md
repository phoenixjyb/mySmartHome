# 洗烘报告：Windows独立静态服务发布

本报告沿用家具报告会话的独立静态托管方式：复用现有HTTPS入口，只将已配置的家庭分享前缀转发给Windows回环地址上的独立静态服务。PhotoHouse的账号、数据库、媒体服务和登录边界保持独立。

## 本地文件与公开页面

- [离线HTML](../../exports/北京洗烘套装选型_2026-10-22.html)：内嵌11张图，可单独离线打开。
- [Markdown研究原稿](北京洗烘套装选型_600与610mm及博西C档_2026-10-22.md)：19品牌证据与安装待确认项。
- `scripts/package_laundry_report.py`：生成公开发布包；仅做本地打包，不连接Windows或发布。

在仓库根目录运行：

```sh
python3 scripts/generate_laundry_report.py
python3 scripts/package_laundry_report.py /absolute/new/package/laundry
```

公开包包括`index.html`和11张去重图片，附带每个文件的字节数与SHA-256清单。现有静态服务的内容安全策略只允许同源图片，因此将内嵌图片拆为ASCII文件名。网页中指向本机Markdown／证据目录的链接改为页内正文／图集；厂家和京东链接保留。无需发布整个仓库或原始JSON数据。

## Windows部署范围

1. 先核实当前独立静态任务、监听地址、正在使用的解释器、配置、服务模块与清单校验值；不要复用历史PID或默认认定某个发布目录仍在使用。
2. 为新版本建立独立发布目录，复制旧的全部允许公开文件，并将新报告放在单独子路径；现有家具V1/V2/V3内容逐字节保留。
3. 合并清单，保持当前分享前缀、回环端口、服务入口和模块不变。配置只更新新目录和清单校验值。私有配置、含随机路径的分享URL、主机信息及操作回执保留在Git之外。
4. 先做新版本静态服务预检。备份静态任务XML及原Action，再仅切换独立静态任务；保留解释器、SYSTEM主体、触发器及其他任务设置。失败时恢复旧Action。
5. 不修改／重启PhotoHouse API、推理任务或网关，不开放新公网端口，不更改证书、DuckDNS、防火墙或相册权限。

已有分享链接可免登录访问；持有链接即获得查看报告的权限。保持`no-store`、`no-referrer`、`noindex`等响应头，并关闭访问日志。随机分享路径不写入Git或普通日志。新报告链接仅在交付给用户时提供。

## 验证与回滚

- 部署前后对比现有任务定义，除静态站任务Action外不应变化；核实API监听进程身份保持一致。
- 从回环HTTP读取每个允许文件，核对长度和SHA-256；从公网HTTPS再次核对，必须正常验证证书，不跳过TLS检查，不携带账号Cookie。
- 确认新增报告的12个文件、原家具报告全部文件、媒体类型及隐私响应头。核实PhotoHouse UI保持原字节、匿名会话接口仍拒绝访问。
- 在浏览器查看实际发布页面的图片与交互。HTTP通过与家庭手机／移动网络实测分别记录。
- 回滚只恢复这次独立静态任务的旧Action／目录，保留新旧发布包和操作回执，不能重置相册数据或其他任务。

实际主机、任务校验值、发布目录和分享URL以本次私有部署回执为准，不将历史部署记录当作当前运行事实。

## 2026-10-22发布结果

本次在既有家庭分享前缀下新增独立的洗烘子路径，仅切换独立静态任务。原家具125个文件逐字节保留，新增12个文件后共137个，全部通过匿名公网HTTPS长度、SHA-256、媒体响应与隐私响应头核验。PhotoHouse UI字节、API进程身份、匿名会话拦截及其他81个任务定义保持一致；静态任务的主体、触发器、设置和解释器保持不变。

实际公网页面已在桌面1440px、手机390px宽度的浏览器检查：11张图加载、档位筛选、19品牌搜索、完整正文入口及图片放大均通过。未进行家庭手机／移动网络实测。
