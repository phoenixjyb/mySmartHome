# 新家报告导航首页：Windows 发布说明

2026-10-22 新增家庭统一入口，汇集四个主要报告和两个早期家具页面。沿用现有 Windows 独立静态报告服务及 HTTPS 分享入口，新增 `home/index.html`；不替换原来的家具总览 `index.html`，六个旧链接保持可用。

## 页面与维护

- [导航首页源码](../../exports/新家报告导航首页_2026-10-22.html)：单文件 HTML/CSS、内联 SVG，无脚本和第三方资源。
- [本地打包器](../../scripts/package_family_report_home.py)：限定六条相对报告链接及两个页内锚点，拒绝私有路径、分享凭据和资源依赖；输出 `index.html` 与字节数/SHA-256 清单。
- 六条目标依次为厨房电器、洗烘、智能家居、家具 V3、阳台 V2.1、法式中古家具总览。前四项集中显示，后两项标为早期方案。
- 导航使用相对路径，面向 Windows 报告树发布；在仓库 `exports/` 里直接打开不能代替正式站点的跳转验证。

```sh
python3 scripts/package_family_report_home.py /absolute/new/package/home
```

## 后续更新流程

1. **修改入口：** 编辑导航首页 HTML 中的卡片标题、摘要和相对链接，保留 `home/index.html` 作为固定总入口。新增、删除或重排报告时，同步打包器的 `REPORT_LINKS`；该列表同时检查首页卡片顺序，不能只改其中一处。
2. **准备报告：** 新报告及其图片等资源先准备完整，核对目标路径。可与首页一起预检和发布，避免首页指向尚未上线的内容。早期页面继续保留，除非用户明确要求下线。
3. **校验打包：** 使用一个新的包目录执行上面的命令，检查页面锚点、相对路径、桌面和手机宽度。无新增资源依赖时继续保持单文件页面；不把随机分享前缀或主机信息写入源码。
4. **更新 Windows：** 重新读取当前运行版本及完整允许清单，基于最新报告树复制新版本。后续首页更新应替换已有 `home/index.html` 的清单项；新增报告则追加其文件。不能重复追加首页、套用首次发布的旧清单，或直接覆盖正在服务的目录。预检后切换独立静态任务，保存本次回滚资料。
5. **交付留档：** 检查正式首页、全部导航目标和返回操作，验证其他报告保护基线及 PhotoHouse 登录边界。新增本次脱敏回执，更新受影响的 `MANIFEST_SHA256.txt` 条目并提交推送；历史回执保留为当时证据。

仅调整首页时，总入口链接保持不变，家人无需重新收藏。只修改这份维护文档不需要重启 Windows 服务。

## 发布范围

用户已授权发布到现有 Windows 网站。首次发布前核验了当时的147个既有允许文件、六个目标及 PhotoHouse 登录边界；复制当时报告树至新版本，只新增首页并合并允许清单。后续更新必须以现场当前完整清单为准，不固定沿用147或148的数量。预检通过后只切换独立静态任务 Action，保存回滚资料。

不改 PhotoHouse 登录、媒体、数据、API、其他任务、HTTPS 网关、证书、防火墙和端口。具体主机、分享链接、任务备份及完整操作回执仅存放在 Git 外私有目录。
